## Layout And Board Contract

- Treat the board shell as a single premium panel that contains both puzzle metadata and the grid. Source: `01-CONTEXT.md` D-01 through D-08.
- Desktop layout is a centered framed composition with a maximum content width of `1200px`, outer page padding `32px`, and a single hero surface holding the board and context.
- Mobile layout is a single-column composition with outer page padding `16px`; preserve board size first and compress metadata into a compact header band inside the same surface.
- Keep the board square at all times. Board width should resolve to `min(72vh, 640px)` on desktop and `min(calc(100vw - 32px), 520px)` on mobile.
- Guarantee a minimum rendered cell size of `40px` for `8x8` boards. Smaller boards may scale larger, but never smaller.
- Render clue numbers centered in their source cells only. Empty cells stay visually quiet and must not imply interactivity in this phase.
- Show progression context inline with metadata as `Puzzle {id}`, `{difficulty}`, and `Puzzle {index} of 40`.
- Provide full starter-pack access through a compact linear navigator inside the shell: `Previous` and `Next Puzzle`. Do not implement a difficulty browser, grid catalog, or completion flow in this phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Hairline offsets, icon gaps, clue inset adjustments |
| sm | 8px | Tight metadata gaps, chip padding |
| md | 16px | Default internal spacing, mobile shell padding |
| lg | 24px | Desktop card padding, board-to-metadata separation |
| xl | 32px | Desktop outer gutters, shell breathing room |
| 2xl | 48px | Large section breaks, immersive framing around the hero shell |
| 3xl | 64px | Desktop top/bottom page spacing |

Exceptions: `44px` minimum for any tap target that gets introduced for `Previous` or `Next Puzzle`; otherwise none. Default from UI-phase spacing contract.

## Typography

Use exactly these four sizes and exactly two weights. This resolves the typography discretion left open in `01-CONTEXT.md`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F3EEE4` | Main app background, board base, empty cells, and the largest reading surfaces |
| Secondary (30%) | `#D9E0DC` | Framed shell layers, metadata chips, clue-cell fill, and subtle dividers |
| Accent (10%) | `#C56D3D` | `Next Puzzle` emphasis, current puzzle id chip, keyboard focus ring, and pack-progress highlight only |
| Destructive | `#B44C3C` | Reserved for future destructive actions only; not used in normal Phase 01 play |

Accent reserved for: `Next Puzzle`, current puzzle identifier chip, focus rings, and pack-progress emphasis. Never use accent for every border, every label, or all interactive text.

Add depth with gradients and shadow, not with extra accent color. The page backdrop may use a soft radial blend from `#F7F3EB` into `#E7DED0`, but the board itself must remain the clearest surface.

---

## Static State Styling Contract

- Clue cells use the secondary surface fill, a `1px` low-contrast border, and `Label` typography at weight `600`.
- Empty cells use the dominant surface with the same border rhythm as clue cells.
- The board shell uses rounded corners of `20px`; internal chips and pills use `12px`; board cells stay square with `8px` rounding only if the grid gap supports it.
- Apply soft elevation only at the shell level. Do not add per-cell drop shadows.
- Hover feedback is limited to metadata controls only. The board grid remains visually static because placement begins in Phase 3.
- Loading state uses shell-level skeleton blocks for metadata and a dimmed board placeholder; do not animate individual cells.
- Error state replaces the board shell body with message and recovery action while retaining the same outer frame.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Next Puzzle |
| Empty state heading | Starter Pack Unavailable |
| Empty state body | No starter-pack puzzles are available yet. Reload the app or restore the bundled puzzle file to continue. |
| Error state | We couldn't load the starter pack. Reload the page to try again. |
| Destructive confirmation | none in Phase 01 |

Use sentence case everywhere. Difficulty labels should render as `Easy`, `Medium`, and `Hard`.

---

## Interaction Boundaries

- Phase 01 is read-only. No drag preview, selection state, validity feedback, or solve messaging is allowed. Source: `01-RESEARCH.md`, Key Finding 3.
- The only phase-appropriate controls are puzzle navigation controls needed to access the shipped set of 40 puzzles.
- Navigation should update the board and metadata in place without changing the surrounding shell composition.
- Keyboard focus must be visible on navigation controls, but the board cells themselves are not focusable yet.
